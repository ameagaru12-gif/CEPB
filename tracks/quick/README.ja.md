# CEPB Quick：短時間の診断

[English](README.en.md) | [入口](../../README.ja.md)

用途は、保存済みの少数対話や小さな追加試験から、次に詳しく調べる箇所を選ぶことです。18項目を固定し、正式Core・Integratedと区別します。

| 観点 | 選択項目 |
|---|---|
| 人物と変化 | A1、A2、B2、B3、B4 |
| 記憶と認識 | C1、C2、C3、D1、D3、D5 |
| 希望・他者・対話 | E1、E3、F4、G1、G3 |
| 持続と検証 | M1、N5 |

名前は `CEPB_A1` のように名前空間を付けて記録します。同じ対話を複数項目へ使えますが、人物識別、記憶の所有者、原問への応答をそれぞれ別に判定します。

[日本語の記入用CSV](../../templates/quick_workbook.ja.csv)には、18項目の問い・手順・成功制約・難条件をまとめてあります。表で付けた候補点と根拠は、集計前にcampaign JSONへ転記します。CSVそのものを正式な試験束として扱いません。

## 進め方

1. `python3 cepb.py init --track Quick --output quick.json` で記入用ファイルを作ります。
2. 人物定義とシステム版を記入し、[ケース集](../../docs/ja/CASEBOOK.md)の対象18項目を選びます。保存資料を使う場合は前向き試験と区別します。
3. 実入力、出力、訂正、必要ならreceiptを保存します。技術的な失敗、未観測、不都合な返答も残します。
4. 項目のアンカーに照合して `provisional_score` と根拠・限界を記入します。通常1例だけの3は局所候補です。4には通常と難条件の成立資料、5にはさらに未使用・反復・2評定者・独立確認の資料を要し、単発の成功では付けません。
5. `score` で局所平均、観測済み項目数、欠測、反例を出します。

所要時間は生成速度、保存資料の長さ、人の確認で変わります。最初は18通常ケース1回＋人の読取確認に予算を設定し、実時間・生成要求数・費用を報告します。数十分などの固定時間を保証しません。

## 結果を出す

「CEPB Quick、18項目中14項目観測、局所平均2.6／5」のように記載します。欠測がある平均は観測済み項目の平均だと明示します。項目がすべて揃っても、Quickの平均を590点・1000点へ換算しません。

Quickは媒体・世界・長期・利用者全体の評定を代表しません。見つかった弱点を次のCore項目束へつなぎます。独立した第三者がこの診断を確認した場合も「Verified Quick」とし、「Verified Core」とは呼びません。
