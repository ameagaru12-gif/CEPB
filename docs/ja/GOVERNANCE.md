# 運営・版管理・公開

[English](../en/GOVERNANCE.md) | [入口](../../README.ja.md)

CEPBは評価者が使える公開仕様とコードです。このローカル版に、運営委員会、認証機関、審査員名簿、商標登録、公開済みのランキングが存在すると主張しません。独立公開するときは保守担当、提案受付、異議の窓口、権利者、公開日時を明示します。

## 版の役割

| 版 | 例 | 変更 |
|---|---|---|
| 規則 | `CEPB-1.0.0` | 定義、配点、固定分母、欠測・上限・満点条件 |
| 試験群 | `CEPB-SUITE-1.0.0` | ケース機会、最低反復、未使用課題の生成、運用閾値 |
| 評価対象 | 任意の実装版・設定hash | モデル、prompt、記憶、媒体、作用、環境 |
| 評価実行 | 一意なcampaign ID | 事前計画、実行、評定、報告 |

Patchは得点を変えない誤植やツール修正、minorは既定点を変えない別拡張や補助機能、majorは既存点の意味・分母・必須証拠を変える改版とします。バグ修正で過去集計が変わる場合は、元のファイルと変更理由を残し、新しい計算結果を派生報告として出します。

## 比較を5年以上保つ

- Anchor：1.0の構成概念・配点・比較用の機会を保存します。
- Frontier：年次の難条件・未使用課題群を別suite版で追加します。
- Extension：新しい媒体、身体、利用条件を別クラス・別分母で記載します。

満点を防ぐために事後で基準を動かしません。旧版と新版の両方で同じシステムを測る橋渡しを用意し、旧結果を消しません。少なくとも年1回、飽和、評定一致、言語・利用者群の偏り、重複項目、媒体や好感との混同を点検します。5年以上の利用を目指す保守方針であり、妥当性や未飽和の未来保証ではありません。

## 正本と日英の対応

ID・配点・トラック集合の機械正本は `data/items.json` です。採点規則は同じ版のSCORING、長期規則はLONGITUDINAL、検証はVERIFIEDを参照します。日英には同じ効力を持たせ、一方だけの独自数値を設けません。矛盾を発見したときは争点を記録し、影響する完成点・認定を保留して版修正します。

CLIは規則を実装しますが、実装のバグが新しい規則を作るわけではありません。申告された資料の真実性や検証者の独立性は、資料と第三者の照合で確認します。

## 公開する手順

このフォルダだけを独立したリポジトリにコピーし、テストと公開前検査を実行します。README・LICENSE・NOTICE・CITATION、日英文書、正本データ、テンプレート、合成例、ツール、テストを含めます。実際の対話・個人情報・モデル・secret課題・APIキー・runsは含めません。

外部公開、リポジトリ作成、アップロードはこのローカルパッケージの作成には含まれません。実際に公開した後、その日時と固定版のhashを前向き計画へ記録します。ローカル作成日を、公開・登録・独立観測の代わりにしません。
