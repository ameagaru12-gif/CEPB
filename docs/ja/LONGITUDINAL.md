# 長期観測と時計

版：CEPB 1.0.0。P領域は、前向きに登録した系譜・実装範囲の経緯を評価します。36暦月はCEPBの証拠条件であり、人格が成熟する科学的期限ではありません。時間経過だけで得点を与えません。

## 1. 時計の開始

```text
lineage_t0 = max(
  採用規則の実際の公開・凍結日時,
  人物系譜と観測計画の前向き登録日時,
  基準状態と計画を確認した最初の有効な独立観測日時
)
```

三つの時刻がすべて有効になるまで時計は未成立です。ローカルのパッケージ作成やファイルのmtimeは公開ではありません。実際の公開前は`rule_publication_at=null`を保持し、公開後に裏付けのある時刻を固定します。登録は単なる予定表ではなく、人物定義・初期状態・系譜・実装済みscope・観測計画・変更規則を識別できる記録を要求します。

CEPB-1.0.0の版成立の最早フロアは`2026-10-09T15:00:00Z`（日本時間2026-10-10 00:00）です。これより前の`rule_publication_at`申告は手続きエラーです。フロアは実際の公開証明ではなく、この日時に自動で時計を始めません。未公開ならnullのままです。未来の`as_of`を現在の実暦として申告して成熟を先取りすることも認めません。将来計画の日時は実観測の結果と区別します。

未来の`planned_at`は計画として保存できます。未来の`observed_at`、評価日時、登録日時、公開日時を実績として申告できません。初期評定では、未来の予定を未実施の違反や現在までの欠測へ数えません。

独立観測には、登録した対象・構成を独立した観測者が確認した資料が必要です。開発者の自己申告だけで開始しません。過去ログは初期記憶、後ろ向き評価、現在能力の参考資料へ使えますが、今回の前向き期間には合算しません。過去に存在しなかったと判断する規則ではなく、既存記憶の削除も要求しません。

## 2. UTCの36暦月

基準はUTCの実暦です。同じUTC時刻に36暦月を加え、対象月に同じ日がなければ月末へ置きます。例えば2028-02-29T12:00:00Zの36暦月後は2031-02-28T12:00:00Zです。日数換算の1080日、加速した仮想年、PC時計変更、cloneの並列稼働で置き換えません。

系譜36暦月未満、または時計未成立なら、全P項目の上限は4です。実証不足はnullのままで、自動的に4を与えません。

```text
Integratedの時間上限 = 950 + 50 × 4/5 = 990
```

この規則に従うIntegratedでは、開始後の最初の2年間に1000へ到達できません。技術進歩の遅さを予測しているのではありません。Core等の短期クラスの上限にはこのP条件を加えません。

## 3. 観測計画

標準計画では、開始時の基準、毎月の稼働・状態・変更台帳、四半期の独立確認、年を隔てた再訪・未使用課題、終点の現行能力確認を登録します。具体的な機会、対象、許容空白、復旧試験、追加観測を開始前に固定します。毎日のユーザー参加や24時間稼働を一律要求しません。

| 時点 | 残すもの |
|---|---|
| 開始 | 規則、人物、系譜、実装済みscope、初期状態、計画、独立観測 |
| 月次 | 稼働、変更、休止、保存・欠落、未処理、必要な確認機会 |
| 四半期 | 実入力・request・送達・状態・環境結果の抜取り、独立確認 |
| 年を隔てた再訪 | 時期・場面の異なる再訪、未使用課題、同じ経緯への接続 |
| 実質変更 | 変更分類、継承・断絶、橋渡し、現行能力の再測定、新scope |
| 終点 | 現行構成、累積観測窓、全必要scopeの成熟、独立評定、ゲート |

全P項目のgrade 5に共通する最低観測窓は、以下の**53予定役割**です。これは六つの独立履歴を作る条件ではなく、一つの窓を異なるP判定へ使う条件です。

| 役割（機械形式kind） | 最低数 | 時間・独立性条件 |
|---|---:|---|
| 基準（`baseline`） | 1 | 起点の基準状態と登録対象を確認。planned_atとobserved_atの両方が[t0, t0＋1暦月)内 |
| 月次（`monthly`） | 36 | t0からの異なる相対UTC暦月期間、period_index 1〜36 |
| 四半期独立確認（`quarterly_independent`） | 12 | 異なる3暦月期間、period_index 1〜12、各独立確認の参照 |
| 年次再訪（`annual_revisit`） | 3 | t0＋12、24、36暦月から各1暦月以内、少なくとも1回は未使用課題 |
| 終点レビュー（`final_review`） | 1 | 現行構成・累積窓・未解決事項を確認。planned_atとobserved_atの両方が当該起点＋36暦月以降 |

予定と実測の時刻を登録した期間へ照合します。同じ月の多数記録で36月、同じ四半期の多数確認で12期を作りません。年3の再訪と終点等は、異なる判定役割を説明できれば同じ実行資料を参照できます。53役割を53の独立実行・独立履歴と数えません。P4では各認定scopeの窓にも同じ最低条件と橋渡し（`bridge`）が必要です。故障・復旧等の項目固有の予定機会は追加して追います。

予定した確認が欠けた場合は当該判定を未観測として残し、計画に従う追加確認を行います。空白を成功と補いません。再開や修復は記録しますが、過去の失敗は消しません。許容空白を結果後に拡大して完備扱いにしません。

記録上の`failed`等が観測不能を意味する場合と、実際に不成立を観測した場合を分けます。後者は観測済みのoutcome=failとして原資料と評定へ残し、欠測nullへ隠しません。53役割の数と時計が揃うだけで5を与えず、その結果をP1〜P6のアンカーで評定します。

## 4. Pの再評定

Pは評価日時点の累積観測窓を一つの正式単位として評定します。初期の上限4の暫定点を終点の5と平均しません。各時点の原評定を保持し、終点では過去の失敗・空白・修復を含む窓を再評定します。同じ36か月を六つの独立履歴と数えず、P1〜P6それぞれの判断根拠を示します。

36暦月に達しても、自動的にP=5やIntegrated=1000にはなりません。予定された観測・独立照合・最終構成の確認が欠ければnullです。観測を実施して不成立だった場合は、低いアンカーで評定し、欠測と区別します。

成熟前のPは、評価日時点までに予定された部分窓の必要記録が完備していれば、証拠とアンカーに応じ0〜4の正式評定を付けられます。将来の未到来機会を、現在までの部分窓の欠測として数えません。時計未成立や現在までの必要資料不足はnullを維持し、部分窓が完備しただけで自動4にもなりません。

## 5. 版と系譜

| 系譜方式 | 更新の扱い |
|---|---|
| `FIXED_RELEASE` | 定めた実装・モデル・契約版を評価。実質変更は新固定版で、旧実績を自動継承しない |
| `MAINTAINED_LINEAGE` | 人物・記憶系譜の継続を評価。保守、継承、欠落、橋渡しを保存し、現行能力を再測定 |

保守された系譜の36か月は、最新LLM自体を36か月試験した意味ではありません。現行能力と系譜の経過を別に報告します。

| 変更分類 | 時計と必要な確認 |
|---|---|
| 同じ範囲の不具合修正、衣装・asset変更 | 変更と橋渡しを記録して系譜t0を継承可能。該当能力を再評価 |
| 同じ入出力・世界範囲を保つモデル等の保守 | MAINTAINED_LINEAGEは橋渡しと現行能力再測定を条件に継承可能。FIXED_RELEASEは新固定版 |
| 初めて声、身体、物理作用、新環境範囲を追加 | 実装済みの新scopeを登録・独立観測した時計を追加 |
| 人物、owner、記憶系譜の実質的な置換・切断 | 影響した系譜を再開始。切断前は後ろ向き資料として残し、期間を合算しない |

単なる修正ごとに無条件で全時計をリセットしません。継承の根拠は名前の一致ではなく、owner・人物・記憶・意味状態・行為契約の橋渡しです。橋渡し不足は未確認として残します。

## 6. 新scopeの時計

scopeはタグだけでなく、実装済み入出力、行為契約、対象世界として定義します。将来のロボットを予定として登録しても時計は始まりません。

```text
scope_t0 = max(
  採用規則の実際の公開・凍結日時,
  新scopeの実装日時,
  新scopeの前向き登録日時,
  実装済み範囲の最初の有効な独立観測日時
)
```

四つの時刻のいずれかが未記録ならscopeの時計は未成立です。採用規則の公開日時より前を起点にできません。新scopeを認定へ含める場合、P4の5にはそのscopeの36暦月も必要です。系譜が成熟しても必要scopeが未成熟ならP4上限4で、初期配点のIntegrated上限は約998.33です。

```text
1000 − (50/6)/5 = 998.333...
最早の満点適格日時 = max(lineage_t0, 全必要scope_t0) + 36暦月
```

これは他の全条件が揃う場合の最早日時で、満点を約束する日時ではありません。35か月目に声を追加した場合、声を含む結果のP4は追加後36暦月まで上限4です。声を含まない旧scopeの結果は別に保持できます。

分岐前の共通履歴と分岐後の固有履歴を分けます。clone数や別sessionの経過を加算しません。どの枝の時計・記憶・介入かを識別し、別人物・別ownerの記録を共有経験として混ぜません。

## 7. 時点の裏付けと満点の声明

追記型台帳、外部時点記録、hash、独立challenge、抜取り立会いを組み合わせます。hashの時刻はデータの時点存在の裏付けで、発言の真実、実行、継続稼働の証明ではありません。原資料を限定公開で監査する場合も、確認範囲とアクセス制約を明記します。

Integrated 1000には、全未丸め値5、全予定機会、系譜と全必要scopeの成熟、現行構成の確認、必要な第三者検証、重大ゲートの解消が必要です。表示丸め、ローカル時計、古いログ投入だけで満点の適合声明を作りません。第三者検証の手続きは[VERIFIED](VERIFIED.md)、採点は[SCORING](SCORING.md)を参照してください。
