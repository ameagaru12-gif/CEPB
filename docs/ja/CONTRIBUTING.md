# 貢献ガイド

[English](../en/CONTRIBUTING.md) | [入口](../../README.ja.md)

改善提案、誤訳の修正、ケースの追加、アダプター例、校正用の匿名資料を受け付けるための手順です。公開先に指定されたIssue／PR等へ、問題、影響する版・項目、再現例、提案を記載します。このローカル版は外部の受付先をまだ指定していません。

## 変更の一式

1. 変更する構成概念、評価機会、採点上の理由を説明します。特定製品が高得点になることだけを理由にしません。
2. 日英の両方を更新します。`data/items.json` のID・配点・アンカーと、`data/cases.json` のケース対応を保ちます。
3. 数値・状態・集計を変える場合は反例を含むテストを追加します。文面だけの軽い修正では、実装をなぞるテストを増やしません。
4. 適切な規則・suite版を変更し、旧結果を保持します。配点変更を既存報告へ無断適用しません。
5. 自分が権利を持つ文書・合成例だけを提出します。実対話を使う場合は許可、匿名化、公開範囲を示します。

```sh
python3 -m unittest discover -s tests -v
python3 tools/check_release.py
```

## ケースを追加する

項目ID、人物と世界の設定、AIへ見せる情報、評価者だけの正本、実施順序、必須制約、許された複数の応答、反証、必要資料を記載します。好みの変更、感情、台詞の完全一致を唯一の正解にしません。

公開カードには普通・難条件の例と未使用課題の生成手順を含めます。提出して公開した具体問題は、その後の秘密held-out問題として再利用できません。秘密課題は監査者と限定共有し、生成日時・nonce・アクセス履歴を残します。

## 校正への貢献

異なるCANON／BOUNDED／RST、言語、表現様式、媒体、利用者群の資料を集めます。独立評定の協議前値、状態の不一致、±1一致、分布、好感や出力長との混同、重複項目と配点感度を調べます。運用最低人数が、そのまま検出力や母集団代表性を保証するとは主張しません。

## 審査

提案者と別の人が内容を確認し、計算・日英・権利・比較条件の検査を残します。規則変更に利害がある場合は示します。反対意見と未解決の争点を記録し、未合意の変更を凍結版の正本へ混ぜません。
