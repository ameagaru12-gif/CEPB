# 第三者検証：Verified

版：CEPB 1.0.0。`Verified`は、宣言した結果・構成・証拠を第三者が独立に確認した状態です。Core等のクラスに付く検証層であり、別の得点、クラス、分母ではありません。CEPBパッケージは公式認証機関を運営せず、公式badgeを発行しません。

## 1. 自己評価との区別

自己評価は、開発や不足発見に利用できます。ただし自己申告のflag、schema検査の成功、開発者と同じLLMの再判定だけでVerifiedにはなりません。検証対象がCoreの一部なら「当該部分の第三者検証」と表示し、Core全体の検証済み完成点と呼びません。

第三者は2名以上の人で、対象実装の当該評価を作成した開発者・初回評定者から独立して再評定します。被験システム自身や補助LLMは人数に数えません。所属、費用の負担、利益相反、過去の関与、実施した役割を報告します。費用を支払ったことだけで独立性を証明したことにはなりません。

## 2. 検証前に固定するもの

検証するクラス・項目・系譜・scope・評価日時、規則とデータの版、実装manifest、試験計画、抜取り規則、重大ゲート、必要資料、異議と再検証の手続きを固定します。成功例だけを監査対象へ選びません。検証側が対象manifest・結果・抜取り計画の同じ版を参照できるようにします。

完全なクラスのVerified声明には、そのクラスの全項目値・欠測状態・ゲート・集計を独立に再確認し、計画に沿った試験の抜取りを行ったことが必要です。抜取りの範囲と未再実行の部分を明記します。危険な実機試験等の再実行ができない場合、保存資料の監査と立会い観測を区別し、未確認範囲を認定しません。

## 3. 実施手順

1. **対象を同定する。** コード・モデル・設定・媒体・環境の版と、実際の実行manifestを照合する。旧版の試験を現行構成の成功へ流用しない。
2. **計画と全結果を確認する。** 予定機会、失敗、技術再試行、欠測、除外、介入を確認する。必要能力の非対応0と観測不足nullを分ける。
3. **原資料を照合する。** 実入力、実request、実際に届いた返答・音声・映像、command、receipt、状態、引用のowner・時点・枝を追う。hash一致を内容の真実と同一視しない。
4. **独立に再評定する。** 初回は開発者の数値、他の第三者の数値、補助LLM候補を見せない。正本と固定アンカーで評定し、協議前の値・根拠・反証を保存する。
5. **試験を抜取り確認する。** 事前に決めた抽出で通常・難条件・未使用条件を確認する。立会い、外部challenge、再実行、保存記録監査のどれを用いたかを記録する。
6. **不一致を協議する。** 原評定を上書きせず、協議記録を追加する。未解決は`disputed`・nullとして残す。多数決だけで不足資料を存在したことにしない。
7. **集計と時計を検査する。** 固定分母、項目重み、完備性、上限、丸め、公開・登録・独立観測、scopeの継承を確認する。
8. **範囲付きの声明を作る。** 確認できた結果と限界、重大ゲート、再検証条件、検証者を併記する。

人の存在感Oは、体験した参加者の原回答が必要です。検証者の「その人は存在感を感じたはず」という推測やLLMの回答では置き換えません。2名の検証者とOの参加者数は別です。

## 4. 記録すべき検証結果

| 記録 | 必要な内容 |
|---|---|
| 対象 | クラス、項目、構成hash、系譜、scope、評価日時 |
| 人 | 匿名化可能な識別子、役割、独立性・利益相反の説明 |
| 確認 | 原資料、抽出計画、実施した抜取り、再実行と未再実行 |
| 評定 | 2名以上の独立した値、根拠、協議前後、未解決事項 |
| 手続き | 介入、版差、欠測、非対応、時間上限、重大ゲート |
| 声明 | 確認範囲、結果、留保、再検証を要する変更 |

機械ツールが検証記録の形式や集計を受理しても、第三者の独立性、証拠の真実、意味判断まで認証したことにはなりません。外部検証者の記録とアクセス可能な根拠が必要です。

## 5. 結果の表示と変更後の扱い

「Core 420/590、CEPB 1.0.0、宣言scopeを第三者2名が再評定・抜取り確認」のように結果と手続きを併記します。欠測があれば完成点の代わりに算術範囲と不足を表示します。監査が失敗を確認した場合も、その失敗は有用な検証結果です。Verifiedを高品質の別名にしません。

重大ゲートが未解決なら満点の適合声明は保留です。軽微な誤読を永久失格にせず、影響範囲と再試験を記録します。モデル、prompt、記憶、媒体、tool、環境の変更後に旧Verifiedを無条件で引き継ぎません。[LONGITUDINAL](LONGITUDINAL.md)の変更分類と橋渡しを行い、現行能力と確認済み範囲を更新します。

Integrated 1000の適合声明には、全未丸め値5、全必要機会、36暦月の系譜と全認定scope、最終構成の確認、必要な第三者検証、未解決重大ゲートなしが必要です。この文書の作成、自己申告、表示上の丸めだけでは条件を満たしません。
