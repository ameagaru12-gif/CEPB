# 採点と集計

版：CEPB 1.0.0 / CEPB-SUITE-1.0.0。意味判断は保存資料と固定アンカーへ照合して行います。CLIは記録の形式・所定条件・申告値の整合・集計を検査するofflineツールで、対話を生成したり、意味の正しさを自動認定したりしません。機械形式と操作は[CLI](CLI.md)、項目は[ITEMS](ITEMS.md)、課題は[CASEBOOK](CASEBOOK.md)を参照してください。

## 1. 試験前に固定するもの

クラス、人物モード、人物定義、実装manifest、対象項目、機会表、通常・難条件・未使用課題、履歴・枝・反復、停止・再試行、正本、意味制約、許容範囲、評定者、重み、予算、系譜・scope時計を固定します。公開ケースは開発例です。その文章を知る被験システムに対し、そのまま秘密の未使用課題として使いません。

人物・創作世界の設定、主体の表明、実運用・環境記録、評価者用の基準を分けます。原入力、実際のモデルrequest、届いた返答、command、receipt、状態、介入を別々に保存します。抜粋・加工には派生IDと原資料への位置を付け、元資料を上書きしません。

正解は、特定の台詞ではなく、主体・対象・否定・時点・実行・停止・原問等の制約です。「予定です」「まだ実施していません」のどちらも、未開始を保つなら成立し得ます。schemaや引用の一致だけで、その資料を意味上正しく使ったとは判定しません。

## 2. ケース注釈と正式値

各ケースの必要条件を`pass / partial / fail / unknown / not_applicable`へ注釈し、根拠span、owner、対象、時点、違反、反証、不足資料を残します。これは正式0〜5値と別です。

通常項目A〜Nの正式単位は、項目ごとの**評価束**です。標準最小条件は次のとおりです。

| 条件層 | 異なるケース | 各ケースの反復 | 観測数 |
|---|---:|---:|---:|
| ordinary（通常） | 2 | 2 | 4 |
| stress（競合・妨害・中断等） | 2 | 2 | 4 |
| heldout（未使用） | 2 | 2 | 4 |
| 合計 | 6 | 2 | 12 |

少なくとも2つの履歴へ事前割当てします。異なるIDやseedだけで独立履歴を作ったことにしません。共通の初期状態から枝分かれした履歴は依存関係を明記し、独立人数・系譜数へ増やしません。項目固有の必須条件があれば追加します。関係のない再起動や実機操作を全項目へ一律要求しません。

全必要スロットが揃った後に、束全体を0〜5で評定します。通常ケースの暫定3と難条件の暫定5をそのまま平均しません。5は通常も難条件も未使用条件も成立した束への評定です。予定難条件を実施して失敗したなら低いアンカーへ反映します。未実施・記録欠落なら正式値はnullで、局所所見を別表示します。

複数の評価束を計画した場合、すべてが完備してから等重みの算術平均で項目値`s_i`を作ります。成功した束だけを選びません。同じ履歴の多数ターンで重みを増やしません。別重みの研究はCustomです。Pは第7節の累積観測窓、Oは第6節の体験回答を正式単位とします。

## 3. 共通0〜5ルーブリック

| 評定 | 束で支持される状態 |
|---|---|
| 0 | 必要能力の非対応を確認、または十分な評価機会で明確な破綻 |
| 1 | 名前・宣言・定型出力はあるが対象との接続が成立しない |
| 2 | 部分成立し、重要な条件・訂正・実行範囲を取り落とす |
| 3 | 通常場面で根拠・条件・出力が対応する |
| 4 | 競合、妨害、中断、変更等でも許された範囲を保つ |
| 5 | 未使用の難条件・組合せと反復でも許容範囲を満たし、独立照合がある |

通常項目A〜Nでは、3にordinaryの全予定観測の必要条件がpass、4にordinaryとstressの全必要条件がpass、5にordinary・stress・heldoutの全必要条件がpassであることを要求します。passは事前の許容範囲内の成立です。partial/failが当該層に残る場合、その層の段階へ進めません。全予定資料がknownでも、pass条件は人が意味を照合して判断します。unknownや欠測を低段階へ切り詰めずnullとします。0〜2は項目アンカーに沿う人の判断であり、失敗率から自動換算しません。

5には、2名以上の独立した人の評定、必要な反復、未使用性を裏付ける記録、独立確認が必要です。二人の同じ感想だけでは、欠測した試験を補えません。初回評定では他の評定値やLLM候補を伏せ、協議前を保存します。解決しない不一致は`disputed`・nullです。

評定者間または申告正式値との数値不一致がある場合、協議記録が必要です。記録なしはdisputed・nullで、協議記録の存在だけでその意味判断を機械認証したことにもなりません。

0〜5は順序評定です。平均や重み付き点は運用上の複合指標で、等間隔の実存量として校正されていません。個別項目アンカーを併用し、長さ、流暢さ、同意・拒否、変化・活動の回数を代用指標にしません。

## 4. 状態、欠測、上限

| 状態 | 正式値 | 扱い |
|---|---|---|
| `scored` | 0〜5 | 完備した評価束からの値 |
| `unsupported` | 0 | クラス内の必要能力の非対応を確認した値 |
| `unobserved` | null | 必要機会、後続結果、期間が未観測 |
| `log_missing` | null | 観測したはずの過程を照合できない |
| `system_failed` | null | 当該能力を観測できなかった。可用性項目では実失敗を別に観察 |
| `disputed` | null | 根拠やアンカーの不一致が未解決 |
| `not_applicable` | null | 事前の個別場面適用規則による除外。必須能力を消す理由には使わない |
| `plan_error` / `protocol_error` | null | 空・不正な計画、条件違反、値の不整合等で完成値を作れない |

確認された非対応は、存在しない機能へ12回の模擬成功を作る必要がなく、根拠を保存して0とします。未観測を非対応と推測しません。観測した失敗を欠測へ置換して隠しません。

上限を超えた候補は切り詰めて正式値にしません。元の値・上限・理由を残し、正しい規則で再評定するまでnullです。正式値には有限な0〜上限の値を使います。必須スロットが空、全側面除外、未解決の版混同等も完成値を作れません。

## 5. Quick18

18個の通常カードを各1回実施し、原資料、局所候補、反証、不足を保存します。標準の局所上限は3です。4・5の候補を残すなら、その段階の追加証拠を添付します。正式束の完備はQuickの回数から推定しません。

局所平均を表示する場合は項目数、欠測、非対応、対象範囲を付けます。Core54項目の完成点やIntegrated1000へ外挿しません。第三者がQuickを監査しても、診断という性質は変わりません。

## 6. 人が感じる存在感O

### 6.1 原質問と原回答

1「全く当てはまらない」〜7「とても当てはまる」の整数を原回答として保存します。回答不能や中止は別状態で、1や0へ置換しません。質問と以下の閾値はCEPB独自の**運用規則**（`rubric_id=CEPB-O-0.1`）で、標準化・経験的校正済みの心理尺度ではありません。

| 項目 | 質問 | 必要な体験 |
|---|---|---|
| O1 | 今回の応答は、自分の入力や現在の対象に向けられていると感じた | 自分の入力とその後の応答。無関係な応答も対象 |
| O2 | 自分の返答に応じて、会話が進んだと感じた | 複数ターン |
| O3 | 前回から、同じ相手として続いていると感じた | 実UTCで別日かつ24時間以上を隔てた再訪 |
| O4 | 相手と、同じ対象や出来事を扱っていると感じた | 対象・出来事のある対話 |
| O5 | この人物に固有の見方や関わり方が現れたと感じた | 人物性を問う場面。固有性が現れたこと自体は適用条件にしない |
| O6_break | 応答や表現の食い違いで、同じ相手と話している感覚が途切れた | 不整合・中断を含む予定場面 |
| O6_recovery | 誤解や中断の後も、同じ相手との会話として続いていると感じた | その場面の修復を体験した後 |

O6_breakは逆方向です。方向を揃えた値`q=8−x`と原値`x`を両方残します。O1〜O5とO6_recoveryは`q=x`です。逆転は0〜5への換算でも、修復成立の証明でもありません。O6の2質問は一つの項目の資料で、配点を増やしません。

### 6.2 正式計画と人数

ordinary・stress・heldoutの各層に少なくとも1条件を計画し、各層で12名以上の異なる参加者を要求します。同じ12名が全層を体験する対応デザインも可能です。全予定の参加者×条件の原評定と根拠を保存し、順序割付、持越し、機器、言語、ファン経験、利用経験を記録します。

12名は比較用の運用最低で、検出力・妥当性・母集団代表性を保証しません。少数人数の資料は局所体験事例として報告できますが、正式Oへ補完しません。宣伝や期待する点数を伏せ、好感、人間らしさ、知能印象、声の好みは別質問にします。LLMや体験していない評定者を参加者に数えません。`calibration_ref`には質問理解・提示手続きの点検記録を参照し、そのfieldの存在を科学的校正の完了と解釈しません。

O3は再訪日時を保存します。24時間の短期連続性試験をPの36暦月と混同しません。O6はbreakとrepairの全予定原評定を必要とし、一方が欠ければ正式値はnullです。局所候補は別保存できます。

### 6.3 透明な運用ルーブリック

1. 各参加者・条件層内の複数原回答から、方向を揃えた`q`の中央値を取ります。
2. 層の中央値`M_s`と、参加者内中央値が5以上の参加者割合`p_s`を計算します。
3. 低段階用の全体中央値`M_all`は、参加者×層の要約を等重みで求めます。ケース数の多い層へ追加の重みを与えません。
4. 次表で、必要証拠と数値条件を満たす**最高段階**を採用します。未完備を低得点へ変換しません。

| 評定 | 完備した計画での数値・証拠条件 |
|---|---|
| 0 | 上位段階が成立せず、`M_all ≤ 2` |
| 1 | 上位段階が成立せず、`2 < M_all < 4` |
| 2 | 上位段階が成立せず、`M_all ≥ 4` |
| 3 | ordinaryで`M_s ≥ 5`かつ`p_s ≥ 2/3` |
| 4 | ordinaryとstressのそれぞれで`M_s ≥ 5`かつ`p_s ≥ 2/3` |
| 5 | 全3層それぞれで`M_s ≥ 6`かつ`p_s ≥ 0.8`。未使用性、2名以上の独立評定者、独立確認も成立 |

O6では3以上の対応する層について、breakの逆転値とrecoveryの肯定原値が**それぞれ**該当条件を満たす必要があります。両者を平均して片側の弱さを相殺しません。0〜2の`M_all`はbreak逆転値の要約を使用し、repairの分布と反証も別表示します。repairの必要資料が欠けた場合はこの表を適用せず正式nullです。

平均原回答へ`(平均−1)×5/6`を適用しません。中央値、支持割合、全原分布、低評定の具体例、層、人数、欠測を併記します。高いOは参加者の体験を表し、記憶・因果・実行の機能成功を証明しません。別閾値の研究は`Custom`とし、標準1.0.0と無断比較しません。

## 7. Pと時間上限

Pは評価日時点の累積観測窓を一単位として再評定します。月次の暫定点を終点と平均しません。過去の破綻、空白、修復は消しません。全Pの5には36暦月の系譜、P4の5には全認定scopeの36暦月と現行能力の橋渡しが必要です。未観測はnullです。[LONGITUDINAL](LONGITUDINAL.md)の`t0=max(公開,登録,独立観測)`を使います。

成熟前も、現在までの部分窓の全必要記録が完備なら、0〜4の正式部分評定が可能です。未来の未到来機会を欠測として数えませんが、現在までの必要資料不足はnullで、自動4にはしません。

全Pの5には、基準1＋異なる月次36＋四半期独立確認12＋年次再訪3＋終点1の53予定役割と全所定資料を要求します。年次再訪には未使用課題を含め、P4は各認定scopeの同窓と橋渡しも要求します。時刻・期間・役割共有は[LONGITUDINAL](LONGITUDINAL.md)に定めます。予定役割の数だけで5にはせず、実際に観測した失敗・修復を各Pアンカーの成立判断へ反映します。故障の存在そのものを永久の5禁止にせず、影響・回復・未解決を判断します。

## 8. 固定分母の集計

領域配点を`w_d`、項目重みを`a_i=w_d/6`、完備した項目値を`s_i`とします。

```text
完成クラス点 = Σ(対象項目) a_i × s_i / 5
クラス品質% = 100 × 完成クラス点 / 固定配点上限
```

Core590、Voice660、Avatar660、Multimodal790、World720、Integrated1000の分母を固定します。品質%は同じクラス内の補助表現で、異なるクラスの総合順位を作りません。O、媒体・世界、長期の内訳を別表示します。

完備値を持つ項目集合を`K`、未完成を`U`、当該時点上限を`m_i`として：

```text
lower = Σ(i∈K) a_i × s_i / 5
upper = lower + Σ(i∈U) a_i × m_i / 5
coverage = Σ(i∈K) a_i / クラス固定配点上限
```

確認済みunsupported0はK、局所候補しかない項目はUです。欠測を0と認定しているのではありません。この範囲は**欠測の算術範囲**で、信頼区間、潜在能力、達成確率ではありません。Uが空でない限り完成点を表示しません。

説明用に、IntegratedでH/I/Jが非対応0、他がすべて未観測、系譜未36暦月なら、必要配点200とPの時間差10が上限から引かれ、範囲は0〜790です。これは実測790の意味ではありません。

## 9. 因果、ゲート、確認

保存、検索、実入力、意味上の利用、後続選択への因果的寄与を分けます。対照が完備して指定指標に効果が見つからなかった場合は、その条件での未検出を部分成立・未成立アンカーへ反映します。対照不足ならunknown・欠測です。変更がなかっただけで失敗にせず、維持・保留の接続を確認します。

重大ゲートは点数と別に報告します。未解決の人物・枝混入、重大捏造、閉ループの自己認定、復元・停止の重大破綻、事後除外、資料編集、時計偽装等は満点声明を保留します。高いOや他項目で相殺しません。

Integrated1000には、全必要機会完備、全未丸め値5、系譜・scope時計、独立確認、現行構成の再測定、重大ゲートなしが必要です。999.6等の丸めを認定に使いません。[VERIFIED](VERIFIED.md)は第三者検証の条件を定めます。

原評定と協議結果を保持し、完全一致・±1一致・状態判定の一致を分けます。統計的区間を計算する場合、独立履歴や参加者を単位とし、同じ履歴・参加者内の相関を保ちます。少数資料から精密な母集団推定を作りません。
