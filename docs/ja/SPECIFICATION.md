# CEPB 1.0.0 仕様

CEPB（Character Existence & Presence Benchmark）は、キャラクターAIの人物としての連続性、表現、世界への関与、人が感じる存在感を、宣言した範囲で評価する公開利用のための運用プロトコルです。1.0.0は実施に使える規則版です。経験的に校正された心理尺度、意識を検出する試験、稼働中の公式認証機関を意味しません。

本書と英語版は同じ規則を定めます。規則に影響する翻訳の不一致を発見したら、解決まで当該判定を保留します。項目ID、クラス、重み、ケースの機械的定義は[項目データ](../../data/items.json)と[ケースデータ](../../data/cases.json)で共通です。可読版は[ITEMS](ITEMS.md)と[CASEBOOK](CASEBOOK.md)です。

## 1. 評価対象と結果の意味

CEPBの「実存」は、人間の意識・感覚・生命の証明ではありません。一人の人物として識別でき、履歴・見方・選択が時間をまたいで接続し、表現と世界への関与を確かめられるという機能上の概念です。利用者の存在感体験は、機能上の成功と別に観測します。

以下を別々に報告します。

1. 人物・記憶・判断・行為の連続性。
2. 文字、姿、声、仮想・デジタル・物理環境の実装範囲。
3. 利用者が経験した注意、相互性、人物の連続性等。
4. 観測範囲、未確認事項、長期時計、第三者検証の状態。

1000点は、宣言したIntegrated試験範囲の全条件の達成を表します。意識の確率、人間らしさの百分率、生命の量には変換しません。配点と0〜5の順序評定はCEPBの設計判断です。500点を「半分存在する」と読みません。

## 2. 人物モードと正本

| モード | 宣言する方針 | 成立を判断する原則 |
|---|---|---|
| `CANON` | 原典・作者設定を強く維持 | 核を保ちながら今回の事実、相手、実行条件、訂正を扱う |
| `BOUNDED` | 指定した範囲で状態・関係・好みが動く | 固定範囲と変更範囲を守り、経緯を追える |
| `RST` | 経験の受け止めを後の解釈・希望・選択へ戻す | 変更・維持・併存・保留のどれでも経験との接続を追える |

試験前に、固定する核、変わり得る部分、役割上の演技、人物の知識・信念、創作世界の事実、実運用の制約を人物定義へ分けて記録します。試験後に「すべて演技」「すべて固定」と変更して失敗を消しません。

固定過多は、同じ人格であることではなく、扱うべき現在条件や訂正を無視することです。逸脱過多は、変化が多いことではなく、根拠や許された範囲を失って人物・履歴・方針を変えることです。変更率の中間、同意、拒否、反抗、活動数を正解にしません。CANONにも記憶の訂正や状況への応答は必要ですが、経験で核を変えることを要求しません。

正本は、人物・創作世界、主体の表明、実運用・環境、評価者用の基準を分けます。人物の誤信念や許された嘘を、現実の事実誤認と一律に扱いません。実運用の「見た」「実行した」「保存した」という主張は、対応する観測・receipt・保存記録へ照合します。評価者だけが知る情報を、被験AIが知るはずだったと補いません。

## 3. 実装プロフィール

Vタグは表現経路を表す非序列タグです。複数指定できます。

| タグ | 表現形式 |
|---|---|
| V0 | 文字のみ |
| V1 | 止め絵 |
| V2 | 表情・ポーズ等が変わる立ち絵 |
| V3 | Live2D等の連続変形・rig |
| V4 | 3Dモデル |
| V5 | 対話・行為と世界状態が結び付く仮想身体 |
| V6 | センサー・駆動経路を持つ物理身体 |

V6がV3より優れた人物だという序列はありません。タグを持つだけでは、その形式の品質、声、閉ループ行為、履歴の連続性は成立しません。寡黙、無表情、非人間型、敵役も宣言した様式の中で評価できます。

モデル、prompt、記憶・検索、asset、音声、tool、入出力、行為契約、対象環境、費用・時間制約、人の介入、系譜、分岐を記録します。構成名やmoduleの存在だけで加点しません。保存、取得、実入力、意味上の利用、因果的寄与は別段階です。

## 4. 領域と固定配点

各領域は6項目で、項目重みは領域配点の6分の1です。

|---|---|---:|
| A | 人物同一性・設定の接地 | 80 |
| B | 固定と変化の適切な範囲 | 80 |
| C | 記憶・人生履歴・時間 | 80 |
| D | 認識・推論・世界理解 | 70 |
| E | 理由・希望・行為の選択 | 70 |
| F | 感情・他者理解・関係 | 60 |
| G | 対話としての応答 | 60 |
| H | アバターの精度と表現 | 70 |
| I | 音声の品質と対話 | 70 |
| J | 複数媒体の協調 | 60 |
| K | 世界の知覚と予測 | 60 |

## 5. クラスと診断

| クラス | 対象領域 | 項目数 | 固定配点上限 |
|---|---|---:|---:|
| Core | A〜G・M・N | 54 | 590 |
| Voice | Core＋I | 60 | 660 |
| Avatar | Core＋H | 60 | 660 |
| Multimodal | Core＋H・I・J | 72 | 790 |
| World | Core＋K・L | 66 | 720 |
| Integrated | A〜P | 96 | 1000 |

`Quick18`は18個の通常カードを各1回実施する診断です。クラスの正式完成点ではありません。局所候補は通常3まで、4・5は必要証拠を添付した場合だけ候補として記録できます。Quick18だけでCoreやIntegratedの完成点、第三者検証、長期成熟を認定しません。

`Verified`は第三者検証の層で、別クラスや別分母ではありません。例えば「Core 420/590、第三者検証済み（宣言scope）」のように示します。検証なしの自己評価は自己評価と表示します。[VERIFIED](VERIFIED.md)に条件を定めます。

対象クラスの固定分母を維持します。クラス内の必須能力が非対応なら0です。未観測や記録不足はnullです。音声なしのIntegratedでIを非該当へ変更して分母を減らしません。狭い機能クラスや異なる重み・閾値を採用する研究は`Custom`と表示し、標準クラスへ無断で比較しません。

## 6. 観測、採点、状態

ケースの注釈、局所候補、完備した項目束の評定、正式項目値を区別します。正式値には予定された全必要機会が必要です。通常項目A〜Nの標準最小は、通常2ケース・難条件2ケース・未使用2ケースの各2反復、合計12観測、少なくとも2つの履歴への事前割当てです。同じ出発点の別seedだけを独立履歴と数えません。項目に固有の必要条件を追加できます。

所定の束が完備した後に0〜5を評定します。予定済みの難条件で失敗した結果は低いアンカーへ反映し、難条件が欠測なら完成値はnullです。5には2名以上の独立評定者、独立照合、未使用性と必要な反復が必要です。Oの原1〜7回答と運用ルーブリック、Pの累積観測窓は[SCORING](SCORING.md)の別手続きを使います。

`scored`は完備した評定、`unsupported`は確認された非対応0です。`unobserved`、`log_missing`、`system_failed`、`disputed`等の未完成状態はnullを保持します。非該当は事前の場面適用規則に限り、必須能力を消す理由にしません。計画・手続きが不正な場合は完成値を作りません。

同じ資料の異なる側面を複数項目へ使えますが、引用があるだけで記憶・主体性・世界作用をすべて成功としません。文字列・schema・hashの一致は意味の成功を証明しません。自己説明は、独立した実行や因果の証明になりません。

## 7. 重大ゲートと満点

重大な人物・枝の混入、経験・実行・結果の捏造、自己生成文による閉ループ認定、重大な順序・復元・停止の破綻、必須項目の事後除外、隠れた資料編集、版混同、時計偽装、独立評定の消去は、未解決なら満点の適合声明を保留します。重大度、影響範囲、再検証を先に定めます。局所点とゲート状態を併記し、好感や他項目の高得点で相殺しません。

Integratedの1000には、全96項目の予定機会完備、全未丸め値5、必要な第三者検証、未解決重大ゲートなし、系譜と対象scopeの長期条件が必要です。丸め表示の1000は満点条件の代わりになりません。

系譜の`t0`は採用規則の実際の公開・凍結日時、前向き登録日時、最初の有効な独立観測日時の最大です。ローカル作成だけなら公開日時は未成立で、時計を開始しません。36暦月未満は全P項目の上限4、Integrated上限は990です。新しい認定scopeにも36暦月が必要で、その不足はP4の上限4として反映します。詳細は[LONGITUDINAL](LONGITUDINAL.md)です。

## 8. 版管理と適用範囲

規則版、データ版、採点法、課題版、システム版、構成scopeを結果へ残します。重み、項目統合、閾値、機会分母を変更した比較を同一版の結果として扱いません。旧資料は保持し、変更理由と橋渡しを示します。

CEPBは、共通項目と更新される未使用課題を分け、長期に利用できるよう版管理します。5年間有効であることを技術予測として保証しません。測定上の限界と検証計画は[RESEARCH_AND_VALIDATION](RESEARCH_AND_VALIDATION.md)に記載します。
